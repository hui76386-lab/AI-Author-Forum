# 作者投稿角色开发任务书

> 文档版本：v1.0  
> 编制日期：2026-08-06  
> 适用项目：AI Author Forum CMS  
> 文档状态：可直接拆分开发任务  
> 前置基线：`docs/cms-development/08-account-and-editorial-access-development-spec.zh-CN.md`

## 1. 目标与决策

项目增加独立的“作者/投稿人”角色。作者可以创建投稿、选择投稿期刊、修改自己拥有编辑权的投稿、保存草稿并提交审核；作者不能审核、投放、静态发布、管理期刊或访问其他作者的稿件。

作者不是 `JournalEditorAssignment` 的一种角色，也不加入“子期刊编辑基础访问”技术组。作者权限必须绑定到具体文章和具体投稿关系，不能用期刊级编辑任命或 `ArticleContributor.name` 字符串推断。

本任务书只定义作者投稿能力，不改变现有编辑角色和正式发布链路：

```text
作者创建/修改自己的草稿
  -> 作者提交初审
  -> 编辑初审
  -> 主编辑终审
  -> 编辑首次投放
  -> 静态构建、manifest 校验、current 原子激活
```

本文件中的作者规则覆盖 08 号任务书中“本阶段不为文章作者自动创建登录账号”和“本阶段不建设作者门户”的范围限制；超级管理员、主编辑、常务副编辑和副编辑的既有权限不因此扩大或缩小。

## 2. 非目标

本阶段不实现以下内容：

- 公共注册、邮箱验证、社交登录或作者自助找回账号；
- 外部同行评审、匿名审稿或作者选择审稿人；
- 作者创建期刊、栏目、期次、版位或静态发布任务；
- 作者修改审核结论、审核意见、投放关系、manifest 或审计日志；
- 作者直接编辑已经通过审核、已投放或已发布的正式版本；
- 以作者姓名、邮箱或文章 `authors` 文本字段作为权限依据；
- 让作者获得 Wagtail 全局页面树、图片库或文档库的通用访问权限。

## 3. 角色与权限模型

### 3.1 角色定义

新增业务角色编码 `author`，中文名称“作者”。账号仍使用现有实名后台账号模型，但作者权限由作者身份和文章授权关系共同决定。

作者账号状态必须为 active，且必须至少有一条有效的文章投稿关系才能进入作者工作台。账号停用后立即失去所有作者写权限，但文章、revision、审核记录和审计记录保留。

作者不加入 `JournalEditorAssignment`。如果同一用户同时是作者和期刊编辑，权限按动作取并集，但作者入口不能成为编辑权限旁路；编辑权限仍由有效期刊任命决定。

### 3.2 动作权限矩阵

| 动作 | 作者 | 副编辑 | 常务副编辑 | 主编辑 | 超级管理员 |
| --- | --- | --- | --- | --- | --- |
| 创建投稿 | 允许，必须指定启用期刊 | 按文章维护职责 | 本刊 | 本刊 | 全平台 |
| 查看自己的投稿 | 允许 | 本刊 | 本刊 | 本刊 | 全平台 |
| 编辑自己的草稿 | 允许 | 按职责 | 本刊 | 本刊 | 全平台 |
| 编辑被退回稿件 | 允许 | 按职责 | 本刊 | 本刊 | 全平台 |
| 提交初审 | 允许，仅自己的可提交稿件 | 本刊 | 本刊 | 本刊 | 全平台 |
| 查看自己的审核状态和意见 | 允许 | 本刊 | 本刊 | 本刊 | 全平台 |
| 查看其他作者稿件正文 | 禁止 | 本刊 | 本刊 | 本刊 | 全平台 |
| 认领、改派或执行初审 | 禁止 | 按审核规则 | 本刊 | 本刊 | 受现有终审规则约束 |
| 执行终审 | 禁止 | 禁止 | 禁止 | 本刊 | 仍不得绕过主编辑终审服务 |
| 创建首次投放 | 禁止 | 禁止 | 禁止 | 本刊 | 全平台 |
| 维护既有投放 | 禁止 | 仅既有本刊投放 | 本刊 | 本刊 | 全平台 |
| 静态构建、激活、重试、回滚 | 禁止 | 禁止 | 禁止 | 仅期刊选择性发布 | 全平台 |
| 修改期刊、栏目、期次、编辑团队 | 禁止 | 按职责 | 按职责 | 本刊 | 全平台 |
| 查看审计日志 | 仅自己文章相关事件的脱敏视图 | 本刊本人动作 | 本刊本人动作 | 本刊 | 全平台 |

作者的“提交审核”不是审核权限。提交动作只允许把文章从 `draft` 推进到 `submitted`，不能直接写入 `approved`、`pending_final` 或发布状态。

## 4. 数据模型

### 4.1 作者投稿关系

新增 `articles.ArticleAuthorship`（名称可在实现评审时调整，但不得复用编辑任命模型）。建议字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `article` | `ForeignKey(ArticlePage, PROTECT)` | 文章删除策略与现有正式文章一致 |
| `user` | `ForeignKey(User, PROTECT)` | 绑定登录账号，不从姓名反查 |
| `role` | choices | `owner` 投稿负责人；`co_author` 共同作者 |
| `can_edit` | Boolean | 默认 owner 为 true，co-author 默认 false |
| `is_corresponding` | Boolean | 每篇文章最多一名有效通讯作者 |
| `invited_by` | `ForeignKey(User, SET_NULL)` | 记录编辑或投稿负责人 |
| `accepted_at` | DateTime nullable | 预留作者邀请确认；本阶段后台可直接确认 |
| `revoked_at` | DateTime nullable | 撤销后立即失去文章权限 |
| `created_at` / `updated_at` | DateTime | 审计和并发排查 |

约束：

1. `(article, user)` 唯一；同一用户不能重复关联同一文章。
2. 每篇文章只能有一个有效 `owner`。
3. 每篇文章只能有一个有效 `is_corresponding=true`。
4. `can_edit=true` 的关系只能授予 owner 或明确接受邀请的共同作者。
5. 关系撤销不删除历史审核记录、revision 或作者公开资料。
6. 文章所属期刊以 `ArticlePage.primary_journal` 为准；作者关系不能扩大期刊数据范围。

### 4.2 与现有 `ArticleContributor` 的关系

`ArticleContributor` 继续保存前台展示的姓名、单位、身份和排序；它不是授权表。实现时可增加可选的 `user` 关联或单独建立映射，但必须满足：

- 没有登录账号的作者仍可作为公开共同作者展示；
- 修改公开作者姓名不会改变账号权限；
- 删除或撤销投稿关系不会删除前台作者声明；
- 文章的 `authors` 汇总字段继续由 contributors 同步生成，不能作为授权判定条件。

### 4.3 投稿元数据

如现有 `ArticlePage.owner` 不足以表达投稿负责人，新增不可编辑的 `submission_owner` 或通过 `ArticleAuthorship(role=owner)` 作为唯一来源。禁止在不同字段中维护两个可能冲突的负责人。

作者提交时必须固定以下审计快照：

- 投稿负责人账号 id；
- 文章所属期刊 id；
- 提交 revision id 和 revision 内容摘要哈希；
- 文章状态和提交时间；
- request id；
- 作者关系版本或更新时间。

### 4.4 期刊投稿配置

在 `journals.Journal` 增加作者投稿配置，至少包括：

| 字段 | 类型 | 默认值 | 规则 |
| --- | --- | --- | --- |
| `accepts_author_submissions` | Boolean | `false` | 只有启用时才出现在作者投稿期刊列表 |
| `submission_guidelines_url` | URL/受控链接 | 空 | 作者提交前展示；必须通过现有公开链接校验 |
| `submission_opened_at` | DateTime nullable | 空 | 用于审计和运营展示，不单独决定是否开放 |
| `submission_closed_at` | DateTime nullable | 空 | 非空且已到期时禁止新投稿 |

投稿可用性必须由服务层统一计算，而不是由模板直接判断：期刊状态为 `active`、投稿开关为真、未处于关闭时间窗，并且存在有效主编辑时才可投稿。数据库迁移默认关闭投稿，避免新功能未经验收突然接收真实投稿。

## 5. 状态与编辑规则

### 5.1 作者可执行的状态转换

| 当前状态 | 作者动作 | 下一状态 | 条件 |
| --- | --- | --- | --- |
| `draft` | 保存修改 | `draft` | 作者拥有 `can_edit`，版本校验通过 |
| `draft` | 提交初审 | `submitted` | 必填字段、分类、作者声明和资源校验通过 |
| `rejected` | 重新开启修改 | `draft` | 只能由审核退回流程生成；作者不能直接伪造 `rejected` |
| `draft`（由退回产生） | 再次提交初审 | `submitted` | 生成新 revision，保留旧审核意见 |

作者不能主动把文章置为 `approved`、`pending_final`、`placed`、`built`、`published` 或 `offline`。

### 5.2 锁定规则

- `submitted`、`pending_final`、`approved`、`placed`、`built`、`published` 状态下，作者不能保存正文、标题、作者声明、分类、封面或静态 slug 修改。
- 编辑退回时，服务层必须将文章置为 `draft` 或现有正式退回状态，并生成可编辑的新 revision 入口。
- 审核中的作者不能通过 Wagtail 原生编辑 URL、预览 URL、批量动作、导入命令或 API 修改锁定文章。
- 已发布文章如需修订，必须由编辑发起受控修订，再重新进入初审和终审；作者不能直接覆盖线上内容。
- 每次作者保存都必须使用 expected revision id 或等价并发校验，冲突时返回 409 并要求重新加载。

### 5.3 创建规则

作者创建文章时：

1. 必须从“启用且开放作者投稿”的期刊列表中选择一个主投期刊；不能创建未指定期刊、全局或跨期刊文章。
2. 服务层在同一事务中创建 `ArticlePage` 草稿和唯一 `ArticleAuthorship(role=owner)`。
3. 初始状态必须为 `draft`，不得自动发布 Wagtail 页面或启动审核 Workflow。
4. 创建者不自动成为期刊编辑，也不获得期刊菜单、文章审核入口或投放入口。
5. 失败时文章和作者关系一起回滚，并记录失败审计。

### 5.4 投稿期刊选择与转投规则

期刊选择是投稿流程中的必填步骤，并直接决定文章的数据范围、初审队列、终审主编辑和后续允许的投放范围。

期刊模型应提供明确的作者投稿开关，例如 `accepts_author_submissions`。作者可选列表必须同时满足：

- `Journal.status == active`；
- `accepts_author_submissions == true`；
- 期刊存在一名有效主编辑；
- 期刊未被暂停投稿或归档；
- 当前作者未被该期刊的受控策略禁止投稿。

作者选择期刊时只能看到公开投稿信息：期刊中英文名称、简介、研究范围、投稿须知链接和是否开放投稿。不得向作者暴露内部编辑名单之外的账号信息、审核负载、稿件数量、版位容量或发布配置。

期刊变更规则：

1. 初次创建草稿时必须选择主投期刊，并写入 `ArticlePage.primary_journal`。
2. 在文章从未提交过审核且仍为 `draft` 时，投稿负责人可以更换主投期刊。
3. 更换期刊必须经过确认页，并在同一事务中重新校验期刊状态、作者权限、文章分类和期刊专属字段。
4. 原期刊分类不能用于目标期刊时必须清除，并要求作者重新选择；不能把不兼容分类静默带入新期刊。
5. 首次提交审核后，作者不能自行修改 `primary_journal`，即使文章后来被退回为草稿也不能直接改刊。
6. 已提交文章需要转投时，由原期刊主编辑或超级管理员执行受控转投；转投必须填写原因、终止当前审核任务、清除原初审分派、重新校验分类，并从目标期刊初审重新开始。
7. 已终审通过、已投放、已构建或已发布的文章不能直接转投；需要按撤销/下线及新投稿流程处理，不能原地改变正式文章所属期刊。
8. 每次作者选择、更换或编辑转投都必须记录原期刊、目标期刊、操作者、revision、request id、原因和结果。

## 6. 作者工作台

### 6.1 入口与页面

建议使用独立的作者工作台，不让作者进入完整 Wagtail 页面树：

```text
/author/
/author/submissions/
/author/submissions/new/
/author/submissions/<article_id>/
/author/submissions/<article_id>/edit/
/author/submissions/<article_id>/submit/
/author/submissions/<article_id>/history/
```

作者工作台必须只返回当前用户存在有效 `ArticleAuthorship` 的文章。任何通过 id、slug、搜索参数或批量接口访问其他文章的请求都必须得到 404 或 403，不得泄露标题、期刊、作者或审核状态。

### 6.2 列表和详情

列表至少显示：标题、期刊、文章类型、当前审核状态、最近修改时间、最近审核意见摘要、是否可以继续编辑、是否可以提交审核。

详情页允许作者查看：自己的文章内容、公开作者信息、自己的审核意见、提交 revision、审核时间线和必要的退回原因。审核人员身份和内部讨论字段按最小披露原则处理；不得显示其他文章、编辑负载、内部改派意见或完整审计日志。

### 6.3 保存与提交

作者提交前必须在页面显示：

- 当前将提交的 revision 标识或更新时间；
- 必填字段校验结果；
- 作者和通讯作者信息；
- 所属期刊和栏目；
- 当前期刊的投稿须知入口；
- 提交后将进入审核并暂时不能继续编辑的提示。

提交按钮调用现有审核 service 的作者授权分支，不允许直接调用模型 `save()` 修改状态。重复 request id 必须幂等，状态已变化时返回明确的冲突信息。

## 7. 权限实现要求

### 7.1 新增的服务层能力

实现以下独立判断，名称可按代码风格调整：

- `can_create_submission(user, journal)`；
- `can_view_submission(user, article)`；
- `can_edit_submission(user, article)`；
- `can_submit_submission(user, article)`；
- `can_view_author_review_feedback(user, article)`。

这些判断必须检查账号 active、文章关系 active、文章期刊范围、文章状态和作者关系的 `can_edit`。不能用 `is_staff`、Wagtail `access_admin`、文章 `authors` 字段、`ArticleContributor.name` 或用户是否曾经提交过 revision 代替。

### 7.2 权限边界

- 作者不授予 `articles.review_article`、`articles.trigger_article_placement`、静态发布相关权限、期刊编辑任命权限或全局 `access_*` 模块权限。
- 如果作者工作台需要登录，只提供专用作者入口权限；该权限不等价于 Wagtail admin 全局入口。
- 所有 POST、服务、Celery 任务和管理命令都必须重复检查对象级作者权限。
- 超级管理员可进行受控排障，但作者文章的审核结论仍必须经过现有主编辑终审 service；不能使用超级管理员旁路替作者审核。
- 作者不能通过图片库、文档库、原始 HTML、导入任务或版本 API 获得跨文章资源读取或写入权限。

### 7.3 与编辑权限的并集规则

同一账号兼任作者和编辑时：

- 作者工作台只显示作者关系拥有的文章；
- 编辑后台仍按有效 `JournalEditorAssignment` 显示本刊范围；
- 编辑权限不能通过作者关系扩大到其他期刊；
- 审计记录必须区分动作来源是作者入口还是编辑入口。

## 8. 审核、投放和发布集成

1. 作者提交调用现有 `submit_article_for_initial_review` 或等价 service，新增 author ownership 校验。
2. 初审、改派、终审仍只调用现有审核 service；作者不能调用这些动作。
3. 审核退回必须写明作者可见的退回原因和内部意见是否可见；作者只能看到标记为公开的意见。
4. 审核通过后，文章只进入“可投放”状态，不自动进入任何 `ArticlePlacement`。
5. 只有主编辑或超级管理员可以首次创建正式投放；作者没有投放 URL、POST 权限或 API token。
6. 静态构建只消费已审核、已投放且通过 manifest 校验的内容；作者保存草稿不能触发前台更新。
7. 作者修改被退回文章后，旧的批准版本必须失效或保持为历史只读版本，新的 revision 必须重新完成初审和终审。

## 9. 审计与安全

作者相关动作至少记录以下 `AuditLog` 事件：账号创建/停用、作者关系授予/撤销、创建草稿、保存 revision、提交初审、重新提交、查看审核意见和权限拒绝。

每条记录包含：actor、目标文章、所属期刊、作者关系 id、动作、旧状态、新状态、revision id、request id、结果、错误摘要和时间。不得写入密码、token、完整正文或未脱敏的内部审核讨论。

安全要求：

- 使用对象级查询过滤和 service 校验双重防护；
- 访问被撤销文章时统一返回 404，避免确认文章是否存在；
- 对作者提交、邀请接受和关系变更使用 CSRF、幂等 request id 和速率限制；
- 文件上传限制类型、大小、存储集合和病毒扫描状态；
- 所有作者输入继续使用现有富文本白名单和 URL 校验；
- 禁止作者使用 raw HTML 权限；
- 账号停用、作者关系撤销和期刊归档后，已有会话必须按现有会话撤销策略失效。

## 10. API 与服务契约

作者工作台可使用 HTML 表单或 JSON API，但两者必须调用同一 service。建议契约如下：

| 方法 | 路径 | 成功 | 失败 |
| --- | --- | --- | --- |
| `GET` | `/author/submissions/` | 当前用户文章分页列表 | 未登录 302/401 |
| `GET` | `/author/journals/` | 返回开放投稿的公开期刊列表 | 未登录 302/401 |
| `POST` | `/author/submissions/` | 根据必填 `journal_id` 创建并返回新草稿 id | 期刊不可投稿 403；校验失败 400 |
| `GET` | `/author/submissions/<id>/` | 返回作者可见详情 | 非本人 404 |
| `PATCH/POST` | `/author/submissions/<id>/edit/` | 返回新 revision id | 锁定状态 409；非本人 404 |
| `POST` | `/author/submissions/<id>/change-journal/` | 首次提交前更换主投期刊 | 已提交 409；目标期刊不可投稿 403 |
| `POST` | `/author/submissions/<id>/submit/` | 返回审核记录 id 和 `submitted` 状态 | 状态冲突 409；校验失败 400；非本人 404 |
| `GET` | `/author/submissions/<id>/history/` | 返回作者可见版本和意见 | 非本人 404 |

所有写接口必须接收或生成 request id，并返回可定位的错误码。禁止向客户端返回数据库异常、对象是否存在的跨范围信息或内部堆栈。

## 11. 迁移与数据策略

本功能不自动把现有编辑账号转换为作者账号，也不根据 `ArticleContributor.name` 批量绑定用户。

迁移步骤：

1. 增加作者账号标识/作者投稿关系表和索引；
2. 为已有文章生成只读的历史 owner 映射（只能在有明确用户 id 的情况下生成）；
3. 没有明确用户 id 的文章保持无人登录编辑状态，由编辑按现有流程维护；
4. 迁移报告列出无法映射的文章、重复通讯作者和无效账号；
5. 新作者入口默认关闭，先用测试账号和测试期刊验收；
6. 开启后只允许超级管理员或主编辑通过受控入口授予作者关系；
7. 迁移不得修改审核状态、approved revision、投放关系、manifest 或正式静态目录。

任何数据修复都必须使用新 revision、审核 service 和审计记录，不能直接批量把旧草稿标记为已审核或已投放。

## 12. 测试要求

### 12.1 单元和服务测试

- 作者只能创建启用期刊下的文章；不能创建全局或其他期刊文章；
- 期刊列表只包含启用、开放投稿且具备有效主编辑的期刊；
- 创建投稿时缺少 `journal_id`、选择关闭投稿期刊或伪造期刊 id 均失败；
- 作者首次提交前可以更换期刊，不兼容分类会被清理并要求重新选择；
- 首次提交后即使文章被退回，作者也不能自行更换期刊；
- 受控转投会终止旧审核任务、清除旧分派并从目标期刊初审重新开始；
- 作者只能查看、编辑和提交自己的有效投稿关系；
- `co_author` 默认只读，明确 `can_edit=true` 后才能编辑；
- 账号停用或关系撤销后，所有作者写操作立即失败；
- `submitted`、`pending_final`、`approved`、`placed`、`built`、`published` 状态下作者编辑被拒绝；
- 退回后作者可以编辑并生成新 revision；
- 作者提交不能直接改变为 `approved` 或启动投放；
- 重复 request id 不重复创建审核记录；
- expected revision 不匹配返回状态冲突，且不写入部分数据；
- 作者没有审核、投放、静态发布、导入和 raw HTML 权限；
- 兼任作者和编辑时，两套范围不会互相扩大；
- 每个越权和成功动作均产生正确审计记录。

### 12.2 集成和端到端测试

至少覆盖：

1. 作者创建草稿、保存、提交初审；
2. 作者从开放期刊列表选择主投期刊，并在首次提交前更换一次期刊；
3. 编辑退回，作者查看公开意见并重新提交，但不能自行更换期刊；
4. 编辑执行受控转投后，目标期刊初审队列和权限范围正确；
5. 编辑初审和主编辑终审后，作者只能看到审核结果；
6. 主编辑创建投放并完成选择性静态发布，作者不能访问投放页面；
7. 两个作者互相访问文章 id、slug、搜索和历史接口均不得泄露数据；
8. 作者尝试 Wagtail 原生编辑 URL、批量操作、导入命令和直接 POST 均被拒绝；
9. 桌面端和移动端作者工作台布局、错误提示、状态锁定和重新提交流程正常；
10. 审核、投放、manifest 和 current 原子激活链路与现有测试保持通过。

## 15. 完成标准

只有同时满足以下条件，作者角色才可启用：

1. 作者只能操作自己的有效投稿关系；
2. 作者不能执行任何审核、投放或静态发布动作；
3. 作者提交的 revision 能被初审和终审准确追踪；
4. 审核中的内容不可被作者修改，退回后可安全重新提交；
5. 现有编辑角色权限矩阵和正式数据链路没有回归；
6. 所有对象级拒绝、状态转换和权限变化都有审计记录；
7. 测试环境完整检查和浏览器验收通过；
8. 没有把作者账号、测试数据、密钥、数据库、媒体或日志带入发布产物。
