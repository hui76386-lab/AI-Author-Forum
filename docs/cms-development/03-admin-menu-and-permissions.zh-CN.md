# 03 后台菜单与权限

## 1. 目标后台结构

后台按业务任务而不是按 Django app 平铺。推荐结构：

```text
内容
  文章
    所有文章
    待审核
    投放同步异常
  子期刊
    子期刊资料
    批量导入
    栏目管理
    栏目变更记录

投放与版位
  人工投放
  系统栏目投放（只读）
  版位管理
  投放同步异常

导航与页面
  主站导航
  子期刊导航
  默认子期刊模板
  内容栏目配置

发布
  静态发布中心
  失败重试
  回滚

系统
  站点配置
  角色权限
  审计日志
```

## 2. 菜单收口原则

当前存在以下职责重叠，整改时应只保留一个主入口：

| 当前重叠 | 统一方案 |
| --- | --- |
| “文章管理”与“所有文章” | “文章”作为主入口，“所有文章”作为列表视图 |
| “文章审核”与自定义审核页 | “待审核”统一进入同一审核服务和权限检查 |
| “投放管理”与“系统栏目投放” | “人工投放”和“系统栏目投放（只读）”明确分层 |
| “投放管理”与“版位管理” | 投放是关系，版位是位置；分成两个子入口 |
| “静态发布”与 `Static publishing` | 只保留“静态发布中心”，英文兼容入口退役 |
| “栏目与导航”“栏目管理” | 子期刊下管理栏目，导航与页面下管理导航基线 |

已定义但未最终注册的 `NavigationGroupViewSet` 和 `ContentColumnConfigViewSet`，在注册前必须先确定它们是否为正式入口；如果只是服务层或兼容层，不应继续出现在代码中作为“半可用 ViewSet”。

## 3. 角色与用户组

业务角色基线：

| 角色 | 应有能力 | 不应有的能力 |
| --- | --- | --- |
| 项目总负责人 | 全部配置、用户权限、审核、发布、回滚、部署决策 | 无 |
| 超级管理员 | 全局配置、用户和组、发布、回滚 | 日常内容批量修改不必默认承担 |
| 内容管理员 | 文章编辑、栏目编辑、投放、预览、提交审核 | 审核、发布、回滚、核心导航写入 |
| 审核人员 | 待审核列表、通过、驳回、审核意见 | 编辑正文、投放、静态发布 |
| 站点运营 | 子期刊资料、封面、图表、SEO、栏目资料 | 审核、发布、用户权限 |
| 发布管理员 | 静态构建、发布、失败重试、回滚 | 修改正文和审核结论 |
| 只读人员 | 查看配置、发布记录、审计日志 | 所有写操作 |

当前自动创建的 Wagtail Workflow 任务组为 `Content Reviewers`，但真实业务用户属于“审核人员”组且该 Workflow 组没有用户。必须统一为一个审核授权来源，推荐将 Workflow Task 绑定到“审核人员”组，并迁移现有用户。

## 4. 权限设计要求

每个入口至少定义：

- 菜单可见权限；
- 列表查看权限；
- 新增/编辑/删除权限；
- 审核或发布动作权限；
- 跨站点/跨期刊范围；
- 审计日志要求；
- 失败后的重试或回滚权限。

不能仅靠菜单隐藏实现安全控制。菜单 hook、ViewSet、service 和 management command 都必须重复做对象级权限/角色检查。

## 5. 高风险动作

以下动作必须有明确 codename、确认页、操作者和审计记录：

- 批量导入/覆盖；
- 审核通过或驳回；
- 文章投放、取消投放、覆盖系统投放；
- 静态构建和 current 激活；
- 失败重试；
- 回滚；
- 修改核心导航、站点配置和发布目录。

审计至少记录：操作者、时间、动作、对象类型、对象 id、旧值摘要、新值摘要、request id、release id、结果和错误信息。

## 6. 权限验收场景

- 内容管理员登录后看不到审核、发布、回滚和角色权限入口；
- 审核人员能处理待审核文章，但不能编辑文章正文或创建投放；
- 发布管理员能重试失败发布，但不能修改文章审核结论；
- 只读人员能查看审计记录，但不能从列表动作按钮触发写操作；
- 项目总负责人拥有全局最高权限，不被业务菜单限制；
- 命令行导入、发布、回滚也必须使用和后台一致的权限/审计策略，不因脱离 HTTP 请求而绕过控制。

## 7. 2026-07-23 审核组与权限收口

- 正式 Workflow task 绑定业务组“审核人员”，不再新建或继续授权英文 `Content Reviewers` 组。
- 数据迁移会把旧英文组成员并入“审核人员”，随后移除旧组的文章审核、正式投放和页面权限，避免同一职责由两套组并行控制。
- 审核、投放、静态发布、重试和回滚仍由 Django/Wagtail permission 在服务或视图入口强制校验；菜单隐藏只改善可见性，不能替代授权判断。
- 项目总负责人和超级管理员保留全局管理能力，但发布、导入、重试、回滚等高风险动作仍必须写入 `AuditLog`；审计写入失败时动作不得被报告为成功。

该收口只落实 07 文档中的保守权限基线，不代表 D-01～D-10 已形成产品决策。
