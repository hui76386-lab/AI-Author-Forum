# 03 后台菜单与权限

> 当前角色基线统一采用 [08 账号、子期刊编辑角色与审核开发任务书](./08-account-and-editorial-access-development-spec.zh-CN.md)：平台超级管理员、子期刊主编辑、常务副编辑和副编辑。旧 Group 只作为迁移来源保留且不再提供业务授权。

## 1. 目标后台结构

后台按业务任务而不是按 Django app 平铺。推荐结构：

```text
内容
  文章
    所有文章
    待审核
    投放同步异常
  子期刊
    子期刊资料
    批量导入
    栏目管理
    栏目变更记录

投放与版位
  人工投放
  系统栏目投放（只读）
  版位管理
  投放同步异常

导航与页面
  主站导航
  子期刊导航
  默认子期刊模板
  内容栏目配置

发布
  静态发布中心
  失败重试
  回滚

系统
  账号管理
    所有账号
    新建账号
    已停用账号
  站点配置
  角色与任命
  审计日志
```

## 2. 菜单收口原则

当前存在以下职责重叠，整改时应只保留一个主入口：

| 当前重叠 | 统一方案 |
| --- | --- |
| “文章管理”与“所有文章” | “文章”作为主入口，“所有文章”作为列表视图 |
| “文章审核”与自定义审核页 | “待审核”统一进入同一审核服务和权限检查 |
| “投放管理”与“系统栏目投放” | “人工投放”和“系统栏目投放（只读）”明确分层 |
| “投放管理”与“版位管理” | 投放是关系，版位是位置；分成两个子入口 |
| “静态发布”与 `Static publishing` | 只保留“静态发布中心”，英文兼容入口退役 |
| “栏目与导航”“栏目管理” | 子期刊下管理栏目，导航与页面下管理导航基线 |

已定义但未最终注册的 `NavigationGroupViewSet` 和 `ContentColumnConfigViewSet`，在注册前必须先确定它们是否为正式入口；如果只是服务层或兼容层，不应继续出现在代码中作为“半可用 ViewSet”。

## 3. 角色与用户组

当前业务角色基线：

| 角色 | 应有能力 | 不应有的能力 |
| --- | --- | --- |
| 超级管理员 | 全平台后台、账号、子期刊、角色、投放、静态构建、激活、重试和回滚 | 不得绕过主编辑终审服务；不得多人共用账号 |
| 主编辑 | 本刊全部文章、编辑团队、初审、终审、本刊期次、首次投放和期刊级自动发布 | 其他期刊、平台账号、全站发布和平台配置 |
| 常务副编辑 | 本刊日常统筹、初审、编辑维护、本刊期次和已有文章重新发布 | 终审、首次投放、账号管理、其他期刊和平台配置 |
| 副编辑 | 本刊初审、被分配的维护职责和已有文章重新发布 | 终审、首次投放、账号管理、其他期刊和平台配置 |

`项目总负责人`、`内容管理员`、`审核人员`、`站点运营`、`发布管理员` 和 `只读人员` 只作为旧系统迁移来源，不作为目标角色。

数据库中可能仍存在 `Content Reviewers` 和“审核人员”等旧组；它们只用于迁移报告，权限已清空。初审和终审必须由 `ArticleInitialReviewTask`、`ArticleFinalReviewTask`、有效 `JournalEditorAssignment` 和统一权限 service 判定。子期刊编辑加入“子期刊编辑基础访问”技术组仅用于后台登录和最小菜单入口，该组不是业务角色。

Wagtail 图片库继续使用共享存储，但图片列表和选择器必须按有效 `JournalEditorAssignment` 过滤：编辑只能选择本刊文章、期次、栏目或素材绑定已经引用的图片以及本人上传的图片；主编辑、常务副编辑和具有 `media_assets` 职责的副编辑可以维护这些图片。账号或任命失效后图片权限立即失效，不能仅依靠菜单隐藏。

## 4. 权限设计要求

每个入口至少定义：

- 菜单可见权限；
- 列表查看权限；
- 新增/编辑/删除权限；
- 审核或发布动作权限；
- 跨站点/跨期刊范围；
- 审计日志要求；
- 失败后的重试或回滚权限。

不能仅靠菜单隐藏实现安全控制。菜单 hook、ViewSet、service 和 management command 都必须重复做对象级权限/角色检查。

## 5. 高风险动作

以下动作必须有明确 codename、确认页、操作者和审计记录：

- 批量导入/覆盖；
- 审核通过或驳回；
- 文章投放、取消投放、覆盖系统投放；
- 静态构建和 current 激活；
- 失败重试；
- 回滚；
- 修改核心导航、站点配置和发布目录。

审计至少记录：操作者、时间、动作、对象类型、对象 id、旧值摘要、新值摘要、request id、release id、结果和错误信息。

## 6. 权限验收场景

- 副编辑和常务副编辑登录后只能看到被分配子期刊的初审、已有文章维护和重新发布入口，不显示新建投放入口；
- 主编辑能处理本刊待初审、待终审和首次投放；投放完成后由系统自动执行期刊级选择性静态发布，但不能管理平台账号或全站发布/回滚；
- 超级管理员能维护全平台，但不能通过全局权限绕过主编辑终审；
- 单独加入旧“只读人员”或其他旧 Group 不产生任何业务访问；
- 旧角色迁移完成后，项目总负责人不再作为系统角色；
- 命令行导入、发布、回滚也必须使用和后台一致的权限/审计策略，不因脱离 HTTP 请求而绕过控制。

## 7. 2026-08-04 账号与权限收口

- Workflow 顺序为初审任务 -> 终审任务；旧英文 `Content Reviewers` 和“审核人员”组不再授予新审核动作。
- 角色迁移会将旧用户按人工映射转换为主编辑、常务副编辑或副编辑及具体子期刊范围，不能自动扩展为全刊权限。
- 审核、投放、期刊级自动发布、全站发布、重试和回滚仍在服务、视图和 Celery 工作进程入口强制校验；菜单隐藏只改善可见性，不能替代授权判断。
- 超级管理员保留全局维护能力，但终审只允许主编辑；发布、导入、重试、回滚等高风险动作仍必须写入 `AuditLog`，审计写入失败时事务回滚。

角色、对象范围和审核边界以 08 号任务书为唯一基线。
